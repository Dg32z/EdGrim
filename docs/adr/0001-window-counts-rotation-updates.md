# 窗口按旋转更新计数，而非客户端 tick

样本窗口以「旋转更新次数」界定：以攻击锚点为中心，向前后各取固定次数的旋转更新。

选择它是因为它与既有录制器、样本格式和特征定义完全一致，不需要迁移历史数据，也不需要改动框架层的 `RotationUpdate`。代价是窗口的真实时长不固定——玩家不动鼠标时窗口跨越的时间会变长——且采样密度与玩家的灵敏度、操作频率相关。

按客户端 tick（C03 family 包）计数是更干净的定义：窗口形状对网络抖动免疫，且能让 28 个 Aim* 检查一并受益。但那会作废全部已有样本，因此留待数据集重新积累时再议。

## Consequences

采样密度与操作频率相关，意味着训练集里「高灵敏度玩家」的样本更多。这会在模型里引入与灵敏度相关的偏差，需要在训练时按玩家做样本均衡，或至少监控该偏差。
