# 模型自动发布，靠自动回滚而非灰度兜底

定时自动重训并自动发布，不设人工确认或灰度环节。风险由自动回滚承担：每次发布后持续做健康检查（裁决分布突变、每模型版本告警量超基线、错误率超阈），异常即自动退回上一个模型版本，同时停止本轮发布并告警。

选它是因为服主不会去点发布按钮，任何人工环节在实践中都会退化成「模型永远停在第一版」。但这也意味着坏模型可能在回滚触发前已经产生误封，所以健康检查是这个决策下唯一的减速带——配合「检查名沿用 AnalysisA、不标 experimental、全量生效」，减速带只剩这一道。

## Considered Options

- **手动训练 + 灰度 + 回滚**：最安全，但每次发布都需要人参与。
- **定时自动重训，人工确认后发布**：折中，但确认环节同样会被跳过，只是把风险推迟到有人偷懒的那一次。

## Consequences

指标不是可观测性的加分项，而是发布流程的必要组件：没有健康检查就没有自动回滚，没有自动回滚这个决策就退化成「在随机时间点全量换模型」。

回滚要求服务端同时保留至少两个模型版本的推理能力，而不是只留最新版。
