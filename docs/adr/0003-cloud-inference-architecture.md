# 云端推理：全量特征上传 + 梯度提升树 + Python 全栈

判定发生在服务端。插件把每个样本的特征向量攒批上传，云端用梯度提升树给出裁决与分数；分类阈值随模型版本下发，裁决权留在本地。

选它是因为本地推理相对已有 28 个 Aim* 检查的增益太小，而云端能在同一批特征上换更强的分类器、且不发版就能更新模型。隐私上只上传归一化后的派生量，ID 按租户 salt 哈希，原始角度不出服务器。

## Considered Options

- **两级混合**（本地先筛、云端复核）：延迟与成本最优，但需要一套本地分类器，且只送可疑样本会让训练集产生选择偏差。
- **云端训练 + 本地推理**：零外发、零请求成本，但模型能力受本地特征集限制，且做不到免发版更新。

## Consequences

窗口补齐本身需要 5 个旋转更新，云端再加一个往返，裁决天然是回溯性的，因此只能靠多样本投票累积，不能单样本即时惩罚。

特征只有 22 维派生量，模型天花板由特征决定。扩特征需要重新积累数据集，所以这个决策的代价是「先接受一个已知偏低的上限」。
